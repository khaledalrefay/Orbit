# المرحلة 6 — النواة: المحرّكات والبيانات

**الحالة:** ⬜ · **تعتمد على:** 3، وصيغة المحتوى من 5 · **نوعها:** كود (Dart صافي ومخزن البيانات)

## الهدف
بناء المنطق كله بلا واجهة: محرّك وقت دقيق، ومحرّك جلسات يشغّل أي تسلسل خطوات، ومحرّك جدولة أسبوعية،
وقاعدة بيانات تحفظ كل شيء بأمان. كل هذا مُختبر بالكامل قبل أي شاشة.

## المدخلات
- منطق Orbit: `state` و `endsAt` و `remaining()` و `restore()` و `STALE` و `MAX_RING` في `index.html`.
- منطق حركة: `domain/engine.mjs` و `domain/schedule.mjs` و `models.d.ts` و `application/workout-service.mjs`
  و `application/backup.mjs` و `infrastructure/workout-repository.mjs`، مع اختبارات `site/tests/vnext/`.

## المهام

### أ. الوقت
- [ ] واجهة `Clock` قابلة للاستبدال (ساعة حقيقية في التطبيق وساعة وهمية في الاختبارات).
- [ ] كل الحسابات من طوابع زمنية (`endsAt`) لا من عدّادات، وهي القاعدة المأخوذة من Orbit.

### ب. محرّك المؤقت (التركيز)
- [ ] الحالات: تركيز، واستراحة قصيرة، واستراحة طويلة، ومع كل منها: جارٍ، أو موقوف، أو منتهٍ (يرن).
- [ ] الجولات، والاستراحة الطويلة كل N جولات، والبدء التلقائي، والتخطي، والإعادة، والتمديد
      (مع `totalMs` لنسبة تقدّم صحيحة كما في حركة beta8).
- [ ] حالة قابلة للحفظ والاستعادة، مع انتهاء صلاحية الجلسة القديمة.
- [ ] أحداث يُبنى عليها لاحقًا: انتهاء المرحلة، والحاجة لجدولة إشعار.

### ج. محرّك الجلسات (مشغّل الخطوات)
- [ ] تحويل روتين استراحة أو جلسة برنامج إلى قائمة خطوات مسطّحة (على غرار `engine.mjs`): مدة، وعدّات، وجهات،
      واستراحات، ومجموعات، ودورات.
- [ ] الانتقالات: التالي، والسابق، والإيقاف المؤقت، والإيقاف أثناء قراءة الشرح، والتخطي، والإنهاء المبكر.
- [ ] Snapshot للمحتوى لكل جلسة، فلا يتغيّر السجل إذا تحدّث المحتوى لاحقًا.

### د. محرّك الجدولة (البرامج)
- [ ] الخطة الأسبوعية: البرنامج، والمستوى، والأيام، وأي جلسة في أي يوم.
- [ ] الاستحقاق، والتعويض (أقرب جلسة فائتة، في أول يوم راحة بعدها، بلا ترحيل بين الأسابيع)،
      وتطبيق التغيير هذا الأسبوع أو القادم (من حركة beta13).
- [ ] توقيت الجهاز بدل دمشق، وبداية أسبوع قابلة للضبط (السبت أو الأحد أو الاثنين).
- [ ] نقل حالات اختبار `schedule.test.mjs` و `week-plan.test.mjs` و `plan-changes.test.mjs` إلى Dart.

### د2. محرّك الترشيح
- [ ] تحويل إجابات onboarding إلى ترشيح: برنامج ومستوى وعدد أيام وأيام محددة، مع سبب مختصر وبديلين.
- [ ] قواعد بسيطة وشفافة (نقاط حسب التطابق مع بيانات الترشيح من المرحلة 5)، بلا تعلّم آلي.
- [ ] اقتراح رفع المستوى بعد عدد من الجلسات المنجزة.
- [ ] اختبارات لكل ملف إجابات نموذجي (مبتدئ بلا أدوات، ومحب للقوة، ووقت قليل…).

### هـ. قاعدة البيانات (drift)
- [ ] الجداول: الإعدادات، وإجابات onboarding، وجلسات التركيز، وجلسات الحركة والبرامج (السجل مع snapshot)، والجلسة الجارية،
      والخطة الأسبوعية والخطة المعلّقة، و body check-ins.
- [ ] معاملات ذرية لإنهاء الجلسة ونقلها للسجل ولتغيير الخطة (كما في حركة).
- [ ] نظام ترحيل (migrations) من الإصدار 1، مع اختبار ترحيل.
- [ ] مستودعات (repositories) بواجهات، تُحقن عبر constructor في Cubits الميزات.

### و. النسخ الاحتياطي
- [ ] تصدير واستيراد بصيغة JSON بإصدار، مع تحقق من البنية والمراجع (على غرار `backup.mjs`).
- [ ] (اختياري حسب قرار المرحلة 1) استيراد صيغة `haraka-v2`.
